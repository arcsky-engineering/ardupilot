Forward Rangefinder Avoidance

Implementation Guide & Test Plan

ArduCopter Custom Feature

1. Overview

The Forward Rangefinder Avoidance system provides obstacle detection and avoidance using a forward-facing rangefinder. When obstacles are detected within a configurable distance for a sufficient number of consecutive samples, the system triggers a configurable failsafe action.

Key Features

  • RC channel master switch for activation (channels 6-11)
  • Optional altitude gating (home altitude or terrain)
  • Mode-specific enable bitmask
  • Configurable threshold distance and sample count
  • Multiple failsafe actions: RTL, SmartRTL, Land, or Stop with stick lockout
  • Automatic escalation to Land if obstacle detected during RTL
  • Continue-if-landing behavior respected

2. Parameters

Parameter Default Range Description
FWDAVD_EN 0 0-31 (bitmask) Enable bitmask for modes:
Bit 0: Auto/Guided/RTL/SmartRTL
Bit 1: Loiter
Bit 2: PosHold
Bit 3: AltHold
FWDAVD_DIST 12.0 1-100 meters Distance threshold for obstacle detection
FWDAVD_SAMP 3 1-20 Number of consecutive samples required to trigger
FWDAVD_COND 0 0-2 Altitude condition:
0 = No altitude check (RC only)
1 = Above home/EKF origin altitude
2 = Above terrain altitude
FWDAVD_ALT 3.0 0-100 meters Minimum altitude for activation (used with COND=1 or 2)
FWDAVD_ACT 0 0-4 Failsafe action:
0 = None
1 = RTL
2 = SmartRTL (falls back to RTL)
3 = Land
4 = Stop with stick lockout (manual modes)
FWDAVD_CHAN 0 0, 6-11 RC channel for master enable switch
0 = Disabled (feature off)
6-11 = RC channel number

3. Activation Logic

3.1 RC Channel Master Switch

The feature requires a valid RC channel (6-11) to be configured via FWDAVD_CHAN.

  • If FWDAVD_CHAN is 0 or outside 6-11 range: Feature is disabled
  • If RC channel PWM ≤ 1500: Feature is inactive
  • If RC channel PWM > 1500: Feature is active (pending altitude check)

3.2 Altitude Gating

After the RC switch is enabled, the altitude condition is checked:

FWDAVD_COND Behavior
0 (None) No altitude check - active whenever RC switch is high
1 (Home Alt) Active only when altitude above home ≥ FWDAVD_ALT
2 (Terrain) Active only when altitude above terrain ≥ FWDAVD_ALT
(Requires valid terrain data; warns if unavailable)

3.3 Mode Enable Check

The FWDAVD_EN bitmask determines which flight modes have avoidance enabled:

Bit Value Modes Enabled
0 1 Auto, Guided, RTL, SmartRTL
1 2 Loiter
2 4 PosHold
3 8 AltHold
Example: To enable for Loiter + PosHold + AltHold, set FWDAVD_EN = 14 (2+4+8)

4. Detection Algorithm

4.1 Rangefinder Reading

  • Uses forward-facing rangefinder (ROTATION_NONE / ROTATION_YAW_0)
  • Requires Status::Good for valid reading
  • Invalid readings (NoData, timeout, etc.) cause counter to decrement

4.2 Counter Logic

If (valid reading AND distance < threshold AND distance > 0):
    Increment counter (up to FWDAVD_SAMP)
    If counter >= FWDAVD_SAMP:
        Trigger failsafe action (if not already triggered)
Else:
    Decrement counter (down to 0)
    If counter == 0 AND was triggered:
        Reset triggered state (obstacle cleared)

5. Failsafe Actions

5.1 Auto Modes (is_autopilot() = true)

When obstacle detected in Auto, Guided, or mission modes:

  • Action 1 (RTL): Switch to RTL mode
  • Action 2 (SmartRTL): Try SmartRTL, fall back to RTL if unavailable
  • Action 3 (Land): Switch to Land mode

5.2 Manual Modes (Loiter, PosHold, AltHold)

When obstacle detected in manual modes:

  • Actions 1-3: Same as auto modes
  • Action 4 (Stop with Lockout):
    • Switches to Loiter (or Brake, or Land as fallback)
    • Locks out roll/pitch stick input
    • Pilot must return sticks to neutral AND obstacle must clear to regain control

5.3 Special Behaviors

RTL Escalation: If obstacle is detected while already in RTL or SmartRTL, the system escalates to Land mode.
Continue-if-Landing: If the vehicle is already landing (is_landing() = true), the system logs the event but allows the landing to continue.

6. GCS Messages

Message Severity Condition
"Forward Avoidance: Active" INFO Feature becomes active (RC + altitude OK)
"Forward Avoidance: Inactive" INFO Feature becomes inactive
"Forward Avoidance: Obstacle detected" WARNING Failsafe action triggered
"Forward Avoidance: Cleared" INFO Obstacle cleared, system reset
"Forward Avoidance: Stop - Return sticks to neutral" WARNING Stop with lockout triggered
"Forward Avoidance: Control restored" INFO Sticks neutral + obstacle cleared
"Forward Avoidance: Continuing landing" WARNING Obstacle during landing (continues)
"Forward Avoidance: Obstacle during RTL - Landing" CRITICAL Escalation from RTL to Land
"Forward Avoidance: No terrain data" WARNING Terrain mode but no data (every 10s)

8. Test Environment Setup

8.1 Hardware Requirements

  • Copter with forward-facing rangefinder (ROTATION_NONE orientation)
  • RC transmitter with available switch on channel 6-11
  • GCS software (Mission Planner, QGroundControl, etc.)
  • Obstacle for testing (wall, barrier, etc.)

8.2 Recommended Test Parameters

FWDAVD_EN    = 15        # Enable for Auto + Loiter + PosHold + AltHold
FWDAVD_DIST  = 12        # 12 meter threshold

9. Test Cases

Test 1: Feature Disabled by Default

Objective: Verify feature is disabled when FWDAVD_CHAN is not configured

Setup: FWDAVD_CHAN = 0 (default)

Steps:

  • Arm and take off in Loiter mode
  • Fly toward obstacle within FWDAVD_DIST
  • Verify no "Forward Avoidance" messages appear
  • Verify no failsafe action is taken

Expected Result: No avoidance behavior, feature fully disabled

Test 2: Invalid RC Channel Rejected

Objective: Verify channels outside 6-11 are rejected

Setup: Try FWDAVD_CHAN = 5, then FWDAVD_CHAN = 12

Steps:

  • Set FWDAVD_CHAN = 5, arm and fly toward obstacle
  • Set FWDAVD_CHAN = 12, arm and fly toward obstacle

Expected Result: Feature remains disabled for both invalid values

Test 3: RC Master Switch Activation

Objective: Verify RC switch controls feature activation

Setup: FWDAVD_CHAN = 7, FWDAVD_COND = 0, FWDAVD_EN = 2 (Loiter)

Steps:

  • Arm and take off in Loiter
  • With RC7 low (≤1500 PWM), verify no "Active" message
  • Switch RC7 high (>1500 PWM), verify "Forward Avoidance: Active" message
  • Switch RC7 low, verify "Forward Avoidance: Inactive" message

Expected Result: Messages appear on state transitions

Test 4: Altitude Gating - Home Altitude

Objective: Verify altitude above home gating works

Setup: FWDAVD_COND = 1, FWDAVD_ALT = 5, RC switch enabled

Steps:

  • Arm and hover at 3m altitude
  • Verify feature shows "Inactive" (below 5m threshold)
  • Climb to 6m altitude
  • Verify "Forward Avoidance: Active" message appears
  • Descend to 4m
  • Verify "Forward Avoidance: Inactive" message appears

Expected Result: Feature activates/deactivates based on home altitude

Test 5: Altitude Gating - Terrain Altitude

Objective: Verify terrain altitude gating works

Setup: FWDAVD_COND = 2, FWDAVD_ALT = 5, terrain data available

Steps:

  • Arm and hover at altitude where terrain AGL < 5m
  • Verify feature shows "Inactive"
  • Climb until terrain AGL ≥ 5m
  • Verify "Forward Avoidance: Active" message appears

Expected Result: Feature uses terrain-relative altitude

Test 6: Terrain Data Warning

Objective: Verify warning when terrain data unavailable

Setup: FWDAVD_COND = 2, no terrain data loaded

Steps:

  • Enable RC switch
  • Wait for warning message

Expected Result: "Forward Avoidance: No terrain data" warning (every 10s)

Test 7: Mode Enable Bitmask

Objective: Verify mode-specific enable works

Setup: FWDAVD_EN = 2 (Loiter only), feature active

Steps:

  • In Loiter mode, approach obstacle - verify avoidance triggers
  • Switch to AltHold, approach obstacle - verify NO avoidance (not enabled)
  • Set FWDAVD_EN = 8 (AltHold only)
  • In AltHold, approach obstacle - verify avoidance triggers
  • Switch to Loiter, approach obstacle - verify NO avoidance

Expected Result: Avoidance only active in enabled modes

Test 8: Obstacle Detection Counter

Objective: Verify sample counting works correctly

Setup: FWDAVD_SAMP = 5, feature active in Loiter

Steps:

  • Briefly pass rangefinder beam across obstacle (1-2 readings)
  • Verify NO failsafe triggers (below 5 samples)
  • Hold steady pointing at obstacle for >0.5 seconds
  • Verify failsafe triggers after 5 consecutive samples

Expected Result: Failsafe requires FWDAVD_SAMP consecutive readings

Test 9: Failsafe Action - RTL

Objective: Verify RTL action works

Setup: FWDAVD_ACT = 1, feature active

Steps:

  • Fly in Loiter toward obstacle
  • Verify "Forward Avoidance: Obstacle detected" message
  • Verify vehicle switches to RTL mode
  • Verify log contains FAILSAFE_FWDAVD error

Expected Result: Vehicle enters RTL on obstacle detection

Test 10: Failsafe Action - SmartRTL

Objective: Verify SmartRTL action works

Setup: FWDAVD_ACT = 2, SmartRTL enabled

Steps:

  • Fly a path to build SmartRTL breadcrumbs
  • Fly toward obstacle
  • Verify vehicle enters SmartRTL mode

Expected Result: Vehicle enters SmartRTL (or RTL if SmartRTL unavailable)

Test 11: Failsafe Action - Land

Objective: Verify Land action works

Setup: FWDAVD_ACT = 3, feature active

Steps:

  • Fly in Loiter toward obstacle
  • Verify vehicle switches to Land mode

Expected Result: Vehicle enters Land mode on obstacle detection

Test 12: Stop with Stick Lockout (Manual Mode)

Objective: Verify stop and stick lockout in manual mode

Setup: FWDAVD_ACT = 4, FWDAVD_EN = 2 (Loiter)

Steps:

  • Fly in Loiter toward obstacle
  • Verify "Forward Avoidance: Stop - Return sticks to neutral" message
  • Verify vehicle enters Loiter and holds position
  • Try to move with sticks - verify NO response (locked out)
  • Clear the obstacle (move vehicle or remove obstacle)
  • Return sticks to center
  • Verify "Forward Avoidance: Control restored" message
  • Verify stick control is restored

Expected Result: Stick lockout until obstacle clear AND sticks neutral

Test 13: RTL Escalation to Land

Objective: Verify escalation when obstacle during RTL

Setup: Feature active, obstacle on RTL path

Steps:

  • Position vehicle so RTL path passes obstacle
  • Trigger RTL (via switch or first avoidance trigger)
  • Allow vehicle to approach second obstacle while in RTL
  • Verify "Forward Avoidance: Obstacle during RTL - Landing" message
  • Verify vehicle switches to Land mode

Expected Result: RTL escalates to Land on second obstacle

Test 14: Continue-if-Landing Behavior

Objective: Verify landing continues when obstacle detected

Setup: Feature active

Steps:

  • Enter Land mode manually or via failsafe
  • During descent, point rangefinder at obstacle
  • Verify "Forward Avoidance: Continuing landing" message
  • Verify vehicle continues landing (does not abort)

Expected Result: Landing continues, obstacle logged but no mode change

Test 15: Obstacle Cleared Reset

Objective: Verify system resets when obstacle clears

Setup: FWDAVD_ACT = 4 (Stop), feature active in Loiter

Steps:

  • Trigger avoidance with obstacle
  • Remove obstacle or reposition vehicle
  • Wait for counter to decrement to zero
  • Return sticks to neutral
  • Verify "Forward Avoidance: Cleared" or "Control restored" message
  • Fly toward same location - verify avoidance can trigger again

Expected Result: System resets and can trigger again

Test 16: Radio Failsafe Interaction

Objective: Verify behavior during radio failsafe

Setup: Feature active

Steps:

  • Trigger radio failsafe (turn off TX)
  • Verify forward avoidance becomes inactive (can't read RC switch)

Expected Result: Feature deactivates during radio failsafe

Test 17: Invalid Rangefinder Reading

Objective: Verify invalid readings don't trigger false positives

Setup: Feature active

Steps:

  • Point rangefinder at sky (beyond max range)
  • Verify no avoidance triggers (Status != Good)
  • Intermittently block/unblock sensor
  • Verify counter resets on invalid readings

Expected Result: Only consecutive valid readings below threshold trigger

Test 18: Disarm State Reset

Objective: Verify state resets on disarm

Setup: Feature active, previously triggered

Steps:

  • Trigger avoidance action
  • Land and disarm (or disarm in air if safe)
  • Arm again
  • Verify all state variables reset (no lingering lockout)

Expected Result: Clean state on rearm

10. Logging Verification

After testing, review logs for:

  • FAILSAFE_FWDAVD errors logged when avoidance triggers
  • Mode changes logged with ModeReason::AVOIDANCE
  • No unexpected errors or crashes

11. Known Limitations

  • Only works with forward-facing rangefinder (ROTATION_NONE)
  • Does not consider vehicle velocity or stopping distance
  • Single sensor - no redundancy
  • Terrain mode requires valid terrain data
  • RC master switch required (no pure-parameter enable)
Test Complete: If all test cases pass, the Forward Rangefinder Avoidance feature is functioning correctly and ready for field deployment.
